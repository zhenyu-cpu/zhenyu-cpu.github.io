> 本文调研 GitHub 上与 [vue-plugin-hiprint](https://github.com/CcSimple/vue-plugin-hiprint) 类似的表单/前端打印开源方案，以及"云打印"服务类开源项目，覆盖模板设计器、浏览器直打、本地打印代理、Linux 打印服务等全链路。文中数据（star 数、更新时间）均通过 GitHub API 于 2026-07-31 实时核实。

## 一、背景：vue-plugin-hiprint 解决了什么问题

在 ERP、进销存、医院、物流、电商等 B 端系统里，"把网页上的表单/单据打印出来"是一个刚需，但实现起来非常痛苦：

- 用浏览器自带的 `window.print()`：只能整页打印，无法精确控制版式、分页、页眉页脚；
- 用截图（html2canvas）转图片打印：模糊、分页困难、不可缩放；
- 用 Lodop/C-Lodop 控件：精度高但闭源、收费、依赖 Windows 和控件安装；
- 后端生成 PDF：要维护模板引擎、排版细节难以调整。

**vue-plugin-hiprint**（[CcSimple/vue-plugin-hiprint](https://github.com/CcSimple/vue-plugin-hiprint)，1.7k ⭐）给出了一条很受欢迎的路：**前端可视化拖拽设计打印模板 → 模板以 JSON 保存 → 运行时填充数据 → 浏览器内预览/直打/导出 PDF**。它内置了文本、条形码、二维码、图片、表格、折线、竖线等控件，并配套 Electron 本地打印服务（electron-hiprint），可以实现"网页 → 本机打印机"免弹窗直打。目前该仓库同时适配 **Vue2 与 Vue3**。

本文以此为主线，调研两条方向的同类开源方案：

1. **表单/前端打印**：模板可视化设计 + 浏览器端打印的库与框架；
2. **云打印服务**：完整的"服务端 + 客户端转发 + 打印机管理"云端打印方案。

## 二、表单 / 前端打印方案

### 2.1 hiprint 生态

#### 2.1.1 hiprint（底层框架）

- **地址**：官方站点 https://hiprint.io（原版为 jQuery 插件）
- **技术栈**：jQuery + 原生 JS
- **核心特性**：可视化模板设计器、套打（连续纸张定位）、条码/二维码/表格/折线控件、导出 PDF、本地打印服务
- **适用场景**：纯 jQuery 项目；作为 vue-plugin-hiprint 的底层内核
- **优缺点**：功能全、生态成熟；缺点是文档分散，部分高级能力需付费获取，且依赖 jQuery。

#### 2.1.2 vue-plugin-hiprint（基准项目）

- **地址**：https://github.com/CcSimple/vue-plugin-hiprint
- **活跃度**：1,697 ⭐，最近提交 2026-05
- **技术栈**：Vue 2 / Vue 3 + hiprint（jQuery）
- **核心特性**：`<hiprint-print-template>` 组件化集成；拖拽设计器；模板 JSON 导入导出；预览、直打、PDF 导出；内置本地打印服务；大量中文示例与 Demo
- **适用场景**：Vue 项目的表单套打（发货单、检验单、处方、标签等）
- **优缺点**：
  - 优点：上手快、示例多、社区大、免费开源；模板设计能力覆盖绝大多数单据场景；已支持 Vue3。
  - 缺点：条码/二维码依赖第三方库；打印服务为官方私有实现，定制受限；复杂场景（如多纸张规格混用）需要自己踩坑。

#### 2.1.3 hiprint 生态衍生项目

- **electron-hiprint**（[CcSimple/electron-hiprint](https://github.com/CcSimple/electron-hiprint)，265 ⭐）：基于 Electron 的静默打印客户端，支持 html 打印、pdf 打印，可作为云打印客户端使用；
- **sv-print-docs**（[CcSimple/sv-print-docs](https://github.com/CcSimple/sv-print-docs)，68 ⭐）：基于 hiprint 的 Svelte 打印设计器组件，也可用于 React、Vue、Angular；
- **easy-print**（[Haru1990/easy-print](https://github.com/Haru1990/easy-print)，63 ⭐）：基于 hiprint 的"打开即用"打印插件；
- **node-hiprint-pdf**（[CcSimple/node-hiprint-pdf](https://github.com/CcSimple/node-hiprint-pdf)，41 ⭐）：服务端生成 sv-print / vue-plugin-hiprint 打印模板图片、PDF、HTML，用于小程序或非 Web 环境预览模板。

### 2.2 轻量打印库（无模板设计器，主打"印指定内容"）

#### 2.2.1 Print.js

- **地址**：https://github.com/crabbly/Print.js
- **活跃度**：4,546 ⭐，最近提交 2026-07
- **技术栈**：vanilla JS，无依赖
- **核心特性**：一键打印 HTML、PDF、图片、JSON；弹新窗口打印；支持页眉页脚、CSS 类名控制
- **适用场景**：轻量页面内容打印，不需要复杂模板
- **优缺点**：极简、零依赖、跨框架；缺点是没有可视化设计器，多页表格分页需要自己写 CSS（`@page`/`page-break`）。

#### 2.2.2 vue-print-nb / vue3-print-nb / vue-print-next

- **地址**：[Power-kxLee/vue-print-nb](https://github.com/Power-kxLee/vue-print-nb)（665 ⭐，Vue2）、[Power-kxLee/vue3-print-nb](https://github.com/Power-kxLee/vue3-print-nb)（95 ⭐，Vue3，更新较旧）、[Alessandro-Pang/vue-print-next](https://github.com/Alessandro-Pang/vue-print-next)（177 ⭐，Vue3，2025-07 更新）
- **技术栈**：Vue 指令（`v-print`）
- **核心特性**：指令式打印指定 DOM；自定义样式、页眉页脚、局部打印区域控制
- **适用场景**：报表、页面局部打印、订单详情等"印当前页内容"的场景
- **优缺点**：用法简单；缺点是无可视化模板设计，复杂套打（条码、连续纸定位）能力弱。

#### 2.2.3 react-to-print

- **地址**：https://github.com/MatthewHerbst/react-to-print
- **活跃度**：2,472 ⭐，最近提交 2026-06
- **技术栈**：React
- **核心特性**：把 React 组件渲染到新窗口并打印，支持打印钩子（onBeforePrint 等）
- **适用场景**：React 项目内组件级打印
- **优缺点**：与 React 集成自然、维护活跃；缺点是无设计器、无 PDF 导出（需自行配合 html2canvas/jsPDF）。

#### 2.2.4 report-designer

- **地址**：https://github.com/xinglie/report-designer
- **活跃度**：1,278 ⭐，最近提交 2026-07
- **技术栈**：HTML/JS（框架无关，也可配合 Vue/React）
- **核心特性**：可视化报表/打印设计器，支持标签、流程图、试卷、SVG、小票、套打等元素编辑
- **适用场景**：需要"可视化设计 + 打印"但不想绑死 Vue 生态的项目
- **优缺点**：设计器能力丰富、框架无关、国产项目文档中文友好；缺点是社区相对 hiprint 较小，条码/二维码能力需自行集成。

### 2.3 DOM → 截图 / PDF（导出报告类）

- **html2canvas**（[niklasvh/html2canvas](https://github.com/niklasvh/html2canvas)，31.9k ⭐）：把 DOM 渲染为 Canvas 位图，是"截图打印"的基础设施；
- **jsPDF**（[parallax/jsPDF](https://github.com/parallax/jsPDF)，31.3k ⭐）：纯前端生成 PDF（矢量/文字/图片），适合程序化拼版；
- **html2pdf.js**（[eKoopmans/html2pdf.js](https://github.com/eKoopmans/html2pdf.js)，4.9k ⭐）：html2canvas + jsPDF 组合，一条 API 导出 PDF。
- **适用场景**：报告导出、无打印机的"存 PDF"需求。
- **优缺点**：实现成本最低；缺点是截图式 PDF 文字不可选、清晰度受屏幕 DPR 影响、多页分页不可控——**不适合精确套打**。

### 2.4 服务端 HTML → PDF（批量/统一渲染）

- **Puppeteer**（[puppeteer/puppeteer](https://github.com/puppeteer/puppeteer)，95.4k ⭐）：Headless Chrome 渲染页面并 `page.pdf()`，支持精确分页、页眉页脚、水印；
- **Gotenberg**（[gotenberg/gotenberg](https://github.com/gotenberg/gotenberg)，12.8k ⭐）：Docker 化的 PDF 生成 API，支持 HTML/URL/Office 转 PDF，自带 Chromium 内核，部署极简；
- **WeasyPrint**（[Kozea/WeasyPrint](https://github.com/Kozea/WeasyPrint)，9.5k ⭐）：Python 实现的 HTML/CSS → PDF，完全遵循 CSS Paged Media 规范；
- **wkhtmltopdf**（[wkhtmltopdf/wkhtmltopdf](https://github.com/wkhtmltopdf/wkhtmltopdf)，14.6k ⭐）：经典方案，基于 WebKit，**已进入维护冻结/归档状态**，新项目建议用 Chromium 系替代。
- **适用场景**：服务端统一出 PDF（报表中心、批量套打、电子单据归档、防篡改水印）。
- **优缺点**：分页精准、可批量、可做权限与审计；缺点是要多一层服务部署，交互式打印（用户点一下就出纸）不适合走这条链路。

### 2.5 Lodop / C-Lodop（闭源对照）

- **地址**：https://www.lodop.net （易桥软件，非开源）
- **技术栈**：Windows 打印控件（Lodop）或本地服务（C-Lodop）+ 浏览器 JS API
- **核心特性**：驱动级打印精度，字体/条码/表格还原度极高；是发票、物流面单、快递单等国内"精确套打"事实标准
- **适用场景**：对精度和合规性要求极高的单据打印
- **优缺点**：精度与兼容性（含老浏览器）一流、国内资料多；缺点是**闭源**、商用需购买授权、依赖 Windows 环境、跨平台和 Web 化困难。

## 三、云打印服务方案

"云打印"的典型架构是：**前端/业务系统 → 打印服务端（队列、权限、模板管理）→ 本地打印代理（把任务转发到本机打印机）→ 打印机**。下面按"客户端代理""服务端""自建云打印"三层介绍开源项目。

### 3.1 本地打印代理（浏览器 → 本机打印机）

#### 3.1.1 qz-tray（强烈推荐）

- **地址**：https://github.com/qzind/tray（旧版 https://github.com/qzind/qz-print ）
- **活跃度**：1,042 ⭐，最近提交 2026-07
- **技术栈**：Java 桌面托盘程序（WebSocket 本地服务）+ 浏览器 JS SDK
- **核心特性**：跨平台（Win/macOS/Linux）；支持**原始打印指令**（ESC/POS、PCL、PostScript、ZPL 等）；可指定打印机、纸宽、份数；安全模型为域名白名单 + 可选的签名证书
- **适用场景**：小票、标签、快递单、发票的"网页触发 → 本机直打"；自建云打印的**标准客户端**
- **优缺点**：行业事实标准、指令级控制、有授权机制、文档完善；缺点是需要给每个客户端安装托盘程序、Java 运行时体积较大、需理解其安全配置。

#### 3.1.2 node-printer / pdf-to-printer（Node 系）

- **地址**：[tojocky/node-printer](https://github.com/tojocky/node-printer)（1,568 ⭐）、[artiebits/pdf-to-printer](https://github.com/artiebits/pdf-to-printer)（493 ⭐）
- **技术栈**：Node.js 原生模块（printer）；Node + SumatraPDF（pdf-to-printer，仅 Windows）
- **核心特性**：node-printer 可在 Node 进程内列打印机、发打印任务；pdf-to-printer 实现 Windows 下静默打印 PDF
- **适用场景**：桌面端（Electron）或 Node 服务端做打印转发；不想装 Java 托盘时的轻量替代
- **优缺点**：生态简单、和业务后端同语言；缺点是 node-printer 需编译原生依赖、跨平台行为差异大，指令级能力弱。

#### 3.1.3 小票/标签专用（ESC/POS）

- **node-thermal-printer**（[Klemen1337/node-thermal-printer](https://github.com/Klemen1337/node-thermal-printer)，917 ⭐）：Node 驱动热敏打印机，支持 USB/串口/网络，含 58/80mm 小票排版；
- **node-escpos**（[lsongdev/node-escpos](https://github.com/lsongdev/node-escpos)，1,575 ⭐）：Node 实现 ESC/POS 指令集；
- **适用场景**：餐饮/零售小票、标签打印的后端或客户端。
- **优缺点**：指令级可控、免费开源；缺点是生态偏小众，需要自己处理打印机兼容性。

### 3.2 服务端打印：CUPS 生态（Linux/网络打印）

- **CUPS**（[OpenPrinting/cups](https://github.com/OpenPrinting/cups)，1,693 ⭐）：Linux 打印服务的事实标准，支持 IPP/网络打印机/打印机共享；
- **cups-filters**（[OpenPrinting/cups-filters](https://github.com/OpenPrinting/cups-filters)，195 ⭐）：驱动过滤链与 PDF 渲染；
- **cups-browsed**（[OpenPrinting/cups-browsed](https://github.com/OpenPrinting/cups-browsed)，52 ⭐）：发现并浏览远程 CUPS 打印机（与 CUPS 2.3+ 配合，是"局域网云打印"的关键组件）。
- **适用场景**：企业内部统一打印服务器、局域网共享打印。
- **优缺点**：纯开源、协议标准（IPP）、生态完整；缺点是配置学习曲线陡、驱动质量参差、浏览器端仍然需要代理（如 qz-tray）配合。

### 3.3 自建云打印：cups-web 与 Electron 壳

- **cups-web**（[hanxi/cups-web](https://github.com/hanxi/cups-web)，1,207 ⭐，Go）：把家用 USB 打印机变成随时可访问的网络打印服务，自带 Web 管理界面，是"低成本自建云打印"的典型代表；
- **electron-hiprint**（见 2.1.3）：可作为云打印客户端，把打印任务通过 Electron 静默转发到本机打印机。

### 3.4 云打印平台与 SaaS（对照参考）

- **PrintNode**（[PrintNode/Desktop](https://github.com/PrintNode/Desktop) 等客户端开源）：商用云打印 SaaS，桌面客户端开源（Windows/macOS/Linux），提供 REST API 下发打印任务、打印机管理。适合"省去自建服务器"的商业云打印，缺点是服务端收费且托管在海外。
- **Google Cloud Print**：已随服务下线（2020-12-31 停止），其生态也随之废弃，仅作历史参考——**新方案不要再依赖任何"云打印协议"大厂，优先选本地代理 + 自有服务端**。
- **飞鹅云打印 / 易联云 / 佳博云（非开源）**：国内小票云打印 SaaS，提供 HTTP API + 云打印盒子/热敏打印机硬件，餐饮、外卖、零售收银场景部署成本最低；缺点是闭源、按量/按硬件收费、数据走第三方平台。
- **Lodop 系的"云打印"版**：Lodop 厂商另有收费的云打印服务，同属闭源商业方案。

### 3.5 自建云打印的推荐架构

```
┌─────────────┐ 模板JSON+数据  ┌──────────────┐  任务队列   ┌──────────────┐  WebSocket  ┌──────────┐
│  前端(Web)   │ ────────────→ │  打印服务端    │ ─────────→ │  本地打印代理  │ ──────────→ │  打印机  │
│ 模板设计/预览 │               │ 权限/审计/模板 │            │ qz-tray/electron-hiprint │ 本机/网络 │
└─────────────┘               └──────────────┘            └──────────────┘             └──────────┘
```

- 前端：`vue-plugin-hiprint` / `report-designer` 做模板设计与预览；
- 服务端：自建队列 + 权限（或 Gotenberg 出 PDF 归档）；
- 客户端：`qz-tray`（通用、指令级）或 `electron-hiprint`（纯前端模板直打）；
- 局域网/服务器场景：CUPS + cups-browsed 或 `cups-web` 做统一打印机管理。

| vue-plugin-hiprint | Vue2/Vue3 + jQuery | 免费开源 | 设计器+预览+直打+PDF+打印服务 | Vue 单据/表单打印 |
| electron-hiprint | Electron | 免费开源 | 静默打印 html/pdf 客户端 | 云打印客户端 |

| Print.js | vanilla JS | 免费开源 | 打印 HTML/PDF/图片/JSON | 轻量内容打印 |
| vue-print-nb / vue-print-next | Vue2/Vue3 | 免费开源 | DOM 指令打印、页眉页脚 | 报表/页面局部打印 |
| react-to-print | React | 免费开源 | 组件打印 | React 项目 |

| cups-web | Go | 免费开源 | USB 打印机网络化 | 家庭/小团队自建云打印 |
| PrintNode | 客户端开源 + 商业服务 | 客户端开源 | SaaS 云打印、API | 免自建服务端 |
| 飞鹅/易联云/佳博云 | 闭源 SaaS + 硬件 | 否 | 小票云打印 API | 餐饮外卖热敏打印 |

## 五、选型建议

1. **Vue 2/3 + 表单套打（发货单/检验单/处方）** → 首选 `vue-plugin-hiprint`，模板设计 + 直打 + PDF 一步到位。
2. **Vue 项目只是"打印当前页面/报表"** → 用 `vue-print-nb`（Vue2）或 `vue-print-next`（Vue3）更轻。
3. **React 项目** → 组件打印用 `react-to-print`；需要模板设计器时封装 hiprint 原生 JS，或用 `sv-print` / `report-designer`。
4. **发票/快递面单等精度敏感、且可接受闭源** → 继续用 Lodop/C-Lodop（精度事实标准）；想开源替代，用 hiprint 系列配合连供纸 CSS 定位。
5. **小票/标签/收银（ESC/POS）** → 浏览器端用 `qz-tray`（指令级、跨平台）；纯后端批量出小票用 `node-thermal-printer`；不想运维就用飞鹅/易联云等 SaaS。
6. **自建云打印平台** → 推荐组合：**前端 vue-plugin-hiprint 系 + 自建任务队列服务端 + qz-tray 客户端**；服务端统一出 PDF 归档叠加 Gotenberg；打印机管理走 CUPS 或 cups-web。
7. **服务端批量 PDF（报表中心、电子单据）** → `Gotenberg`（部署最简）或 `Puppeteer`（定制力最强）或 `WeasyPrint`（CSS 规范最严谨）。

一句话总结：**要"设计模板 + 交互式打印"用 hiprint 生态；要"云打印的本地转发"用 qz-tray；要"服务端批量 PDF"用 Gotenberg/CUPS 系**——三者可以自由组合成完整的开源打印链路。
